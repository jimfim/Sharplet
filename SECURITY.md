# Security Policy

## Supported Versions

Only the latest release of Sharplet receives security updates. Pin your deployments to a specific version and monitor for newer releases.

## Reporting a Vulnerability

**Please do not open a public GitHub issue for unpatched or unknown vulnerabilities.**

Instead, report vulnerabilities privately through [GitHub Security Advisories](https://github.com/jimfim/Sharplet/security/advisories/new). Include:

- A description of the vulnerability and its impact.
- Reproduction steps or a proof-of-concept.
- Your assessment of severity (if known).

The maintainer aims to acknowledge reports within 72 hours and will provide an estimated timeline for a fix or mitigation. There is no guaranteed SLA — this is an open-source project maintained on a best-effort basis.

Once a fix is available, the advisory will be published via the GitHub Security Advisory process so affected users can update promptly.

## Scope

This policy applies to the following projects in the Sharplet repository:

- `Sharplet.Core` (NuGet library)
- `Sharplet.Samplekubelet` (virtual kubelet host application)

Code outside these packages is provided as examples only and is not in scope for security fixes under this policy.
